# QA 테스트케이스 — 로그인/인증

> 작성: 2026-05-19 | 업데이트: 2026-05-21

## 대상
- 이메일/패스워드 로그인 (✅ 구현 완료)
- 카카오/Google OAuth (🔄 미구현 — 추후 테스트케이스 추가)

## P0 승인 기준
정상 플로우 (TC-001~004) + 에러 처리 (TC-005~007) + 세션 유지 (TC-008~009)

---

## TC-001 · 신규 회원가입 (정상)
- **입력**: 유효한 이메일, 6자↑ 패스워드, 닉네임
- **기대**: 이메일 인증 안내 Alert → 로그인 탭으로 전환
- **확인**: Supabase Auth에 사용자 생성, public.users 프로필 자동 생성

## TC-002 · 로그인 (정상)
- **입력**: 가입된 이메일 + 올바른 패스워드
- **기대**: 홈 화면으로 이동
- **확인**: localStorage(Web) / SecureStore(Native)에 세션 저장

## TC-003 · 로그아웃
- **입력**: 설정 → 로그아웃 → 확인
- **기대**: 로그인 화면으로 이동
- **확인**: 세션 스토리지 삭제

## TC-004 · 앱 재시작 시 세션 유지
- **입력**: 로그인 후 앱 종료 → 재시작
- **기대**: 로그인 화면 없이 홈으로 바로 이동

## TC-005 · 잘못된 비밀번호
- **입력**: 존재하는 이메일 + 틀린 패스워드
- **기대**: "이메일 또는 비밀번호가 올바르지 않습니다" Alert

## TC-006 · 비밀번호 불일치 (회원가입)
- **입력**: 패스워드 ≠ 패스워드 확인
- **기대**: 실시간 "비밀번호가 일치하지 않습니다" 표시, 가입 버튼 동작 시 Alert

## TC-007 · 이미 가입된 이메일 (회원가입)
- **입력**: 기존 이메일로 재가입 시도
- **기대**: "이미 가입된 이메일" Alert

## TC-008 · 패스워드 6자 미만 (회원가입)
- **입력**: 5자 패스워드
- **기대**: "비밀번호는 6자 이상이어야 합니다" Alert

## TC-009 · 이메일 형식 오류
- **입력**: `abc`, `abc@`, `@test.com`
- **기대**: "올바른 이메일 형식이 아닙니다" Alert

## TC-010 · 비밀번호 표시/숨기기 토글
- **입력**: visibility 아이콘 탭
- **기대**: secureTextEntry 토글, 아이콘 변경 (visibility ↔ visibility_off)

## 테스트 환경
- Web: Chrome (localhost:8081)
- iOS: Expo Go
